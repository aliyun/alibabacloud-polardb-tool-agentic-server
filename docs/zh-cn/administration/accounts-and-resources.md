# 账号与资源

[English](../../en/administration/accounts-and-resources.md)

账号说明**谁在访问 PAS**，资源说明**可以访问什么**。每个账号在资源上有各自允许的操作。

| 概念 | 含义 | 控制台入口 |
| --- | --- | --- |
| 个人账号 | 现有 PAS User，通过 SSO 或本地登录认证 | 访问管理 → 个人账号 |
| 服务账号 | 代表应用的现有 Agent | 访问管理 → 服务账号 |
| 资源 | 数据库或已启用的知识目录条目 | 资源 |
| 凭据 | 身份证明，不是另一套权限 | 连接 MCP，或服务账号连接配置 |

服务账号的创建者不会继承该服务账号的权限。SSO 是个人账号的登录方式，不是另一类账号。
现有 User、Agent 和绑定标识保持不变；此功能不需要元数据 schema 迁移（`NONE`）。

## 授予数据库访问权限

1. 打开**资源 → 数据库**，选择资源并进入**管理授权**。
2. 选择**添加授权**、个人或服务账号，以及属于该资源的有效 `direct_access` 数据库凭据。
3. 选择**查询数据**（`sql:read`）或**查询与写入数据**（`sql:read`、`sql:write`）。两者都包含资源发现和描述。只读凭据不能授予写入权限。
4. 保存。同一绑定也会出现在**访问管理 → 账号 → 管理授权**中；两侧操作更新同一条现有绑定。

SQL 预设会保留独立配置的凭据查看和供应能力。这些能力仍在**高级设置**中管理，同处的还有
连接配置、凭据、企业身份和容量管理。添加 SQL 预设不会授予创建实例的权限。

授权表展示已配置的授权及来源：直接授权、系统分配、用户组继承。执行时还会检查当前账号、
资源和凭据状态。继承权限需在来源用户组管理；现有用户组模型支持多租户分配，不支持任意
数据库凭据授权。将系统分配编辑为显式授权需要有效的直接访问凭据。

**禁用授权**会保留一条禁用绑定。对个人账号，这也会阻止同一资源的继承访问；直接删行可能
反而恢复继承权限。禁用数据库访问不会删除数据，也不会移除服务账号独立的供应授权。
变更会记录审计，后续请求重新检查权限。

## 连接个人账号

打开**我的资源**查看自己的数据库和知识库访问范围，再进入**连接 MCP**。
不需要 Agent 分配或默认 Agent 选择。使用页面显示的地址，例如：

```json
{
  "mcpServers": {
    "pas-personal": {
      "type": "http",
      "url": "https://PAS_HOST/mcp/personal"
    }
  }
}
```

OAuth 客户端发现 `/.well-known/oauth-protected-resource/mcp/personal`，并将个人 URL
作为授权 `resource`。Authorization Code with PKCE 和 Refresh Token 保持该 audience。
未指定个人 resource 的客户端会得到旧 audience，该 Token 无法用于 `/mcp/personal`。

不支持 OAuth 的客户端可在 **Token 连接**页签生成 `pas_personal_` Bearer Token。
每个用户同时只有一个有效 Token，有效期 1–365 天（默认 90 天）。从一次性弹窗复制，配置
`Authorization: Bearer TOKEN`。PAS 仅保存哈希，列表不会返回明文；更换前先吊销旧 Token。
吊销、到期、账号禁用及凭据 epoch 变更均会使 Token 失效。管理员无法获取其他用户的个人
Token。个人 Token 不能用于控制台 REST 请求，也不能作为 Refresh Token 交换。

个人 Token 使用当前个人权限，没有独立的资源范围。仅有 SQL 的个人授权也允许发现和描述
资源，但不会显示数据库密码。个人客户端不能创建或删除服务账号拥有的数据库，也不能选择服务账号。

SQL 工具需要显式 `instance_id`；个人 MCP 不开放分支或默认实例操作。未配置外部地址时，控制台使用当前浏览器 origin 构造 Token 连接地址，并提示 OAuth 不可用，需管理员配置 `runtime_policy.external_base_url`。外部地址变更后，请吊销并重新生成个人 Token。

## 知识库访问

知识库保持可选，按照[知识库启用指南](../knowledge/activation.md)在**高级设置 → 功能设置**
启用。禁用后，知识库从资源发现和 MCP 工具中隐藏，数据库访问继续可用。

资源页面提供知识库配置与权限来源说明。可见性继续由企业身份和所有权决定。每次搜索或文档读取
都向上游发送员工解析后的 ACL 上下文，由上游执行文档权限检查。没有新增逐用户知识库授权表，
也没有覆盖上游 ACL 的本地授权。个人 MCP 支持知识读取；已有的委托 Agent 连接继续提供配置好的
上传和管理流程。

## 现有连接与回滚

`/mcp`、`pas_agent_`、`pas_user_agent_`、workspace 选择以及外部 Token Exchange 保持原语义。
**连接 MCP → 已有 Agent 连接与文档上传**打开兼容视图。个人 Token 不能访问 `/mcp`，旧凭据
不能访问 `/mcp/personal`。

不会将现有授权复制或合并进个人账号。将员工从 workspace 连接迁移时，需明确审查并添加个人
数据库授权。旧镜像不支持新的个人端点和 audience；回滚镜像时保持未变的 schema，用户仍可使用
原有旧连接。目标版本完成滚动发布前，不应只依赖新端点。代理需转发 `/mcp/personal` 及其
受保护资源元数据路径。
