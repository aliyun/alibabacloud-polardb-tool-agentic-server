# 企业身份源

[English](../../en/administration/enterprise-identity-sources.md)

企业身份源会导入飞书或 SharePoint 租户的目录事实，并使其可用于已启用的 PolarRAG Space。
PAS 使用 `PAS_ENCRYPTION_KEY` 加密全部密钥。飞书变更通过 PAS 主动建立的长连接到达，并由
按条件触发的全量对账兜底；SharePoint 继续使用已配置的轮询周期。PAS 在服务端构造
`acl_context`，PolarRAG 仍是文档访问的最终裁决方。

控制台的**接入指南**入口先提供**飞书接入**和**SharePoint 接入**两个链接；选择后仅展示
对应来源的配置步骤，并可使用页面顶部的 `A−`、`A`、`A+` 调整阅读字号。身份源列表会在
来源名称下方显示 PAS 身份源 UUID，并提供复制操作，供 API 接入时使用。

## 开始前

需要准备：

- 一个 PAS 管理员账号；
- 已注册 PolarRAG 实例，且目标 Space 已启用；以及
- 一个在文档所属企业中注册的身份提供商应用。

每个已验证身份源均可绑定多个已启用 Space。Space 的 `identity_domain` 来自 PolarRAG Space
目录，不是管理员输入，也不要求等于 Space ID。

新增身份源时，控制台默认勾选**绑定所有 Space（包括以后新增）**。PAS 会建立当前全部已启用
Space 的父级绑定，并在以后注册新 Space 时为仍采用该默认策略的身份源建立绑定。取消勾选后，
该身份源仅使用管理员在**绑定 Space**弹窗中明确建立的关系。

已保存的身份源配置无法读取或格式损坏时，不再自动绑定 Space，并记录不含凭据的告警。
已有绑定不变。旧配置缺少绑定策略字段时仍保留默认行为；字段存在时必须为布尔值。

## 配置 SharePoint 身份源

SharePoint 来源通过 Microsoft Graph 同步 Microsoft Entra 目录中的用户、用户组，以及用户或
嵌套用户组的直接成员关系。同一个 Entra 应用还为 PAS 用户提供免密码的 SharePoint 登录。

SharePoint 接入分为三步：先在 PAS 配置外部访问地址，再在 Microsoft Entra 注册并授权应用，最后回到
PAS 创建身份源。

### 第一步：在 PAS 配置外部访问基础 URL

PAS 是 **PolarDB Agentic Server**，即当前 MCPServer 的管理控制台和认证服务。若需要使用
SharePoint 登录，在 PAS 中进入**设置** > **配置** > **服务运行策略**，将**外部访问基础 URL**设置为
用户浏览器可访问的 HTTPS PAS 地址，执行检查并激活配置。例如：

```text
https://pas.example.com
```

仅测试目录同步时，PAS 会主动调用 Microsoft Graph，不需要配置重定向 URI。测试或上线 SharePoint 登录时，
该基础 URL 必须与下一步的 Entra 回调地址使用相同主机、协议和端口。

### 第二步：在 Microsoft Entra 注册并配置应用

先确认 Entra 租户所属环境：

| 环境 | 适用租户 | 应用注册门户 |
| --- | --- | --- |
| 全球云 | 全球 Azure / Microsoft 365 租户 | [Microsoft Entra 管理中心](https://entra.microsoft.com/) |
| 中国云（世纪互联） | 由世纪互联运营的 Microsoft 365 中国租户 | [Azure 中国门户](https://portal.azure.cn/) |

进入上一步对应门户中的**Microsoft Entra ID** > **应用注册** > **新建注册**，选择**仅此组织目录中的
帐户（单租户）**。创建后从**概述**
复制目录（租户）ID 和应用程序（客户端）ID。

然后进入**证书和密码** > **客户端密码** > **新客户端密码**，填写说明并选择有效期后创建。立即复制
新密码的**值**，并填入 PAS 身份源表单的**客户端密钥**；不要填写密码 ID。该值只显示一次，过期后需
创建新密码并在 PAS 中更新配置。

配置来源前，先进入 **设置** > **配置** > **服务运行策略**，将**外部访问基础 URL** 设置为
与下方登录回调相同主机、协议和端口的 PAS 地址，并激活配置。线上环境例如：

```text
https://pas.example.com
```

在 Entra 应用注册页进入**API 权限** > **添加权限** > **Microsoft Graph** > **应用程序权限**，添加以下
权限；随后点击**代表 <租户名称> 授予管理员同意**，确认两项均显示“已授予”。

| 权限 | PAS 使用原因 |
| --- | --- |
| `User.Read.All` | 枚举 Entra 用户及其稳定对象 ID。 |
| `GroupMember.Read.All` | 枚举用户组和直接成员关系。 |

仅测试目录同步时，注册页面中的**重定向 URI（可选）**可以留空；该同步由 PAS 主动调用
Microsoft Graph。只要测试**使用 SharePoint 登录**，包括线下测试，都必须进入**身份验证** >
**添加平台** > **Web**，填写完整的 HTTPS 回调地址：

```text
https://pas.example.com/auth/sharepoint/login/callback
```

如果应用已经创建，可进入**身份验证**并选择其 **Web** 平台。使用**添加 URI**新增另一个 PAS 回调地址，
或直接编辑已有地址进行替换；每次修改后保存平台配置。每条重定向 URI 必须唯一，已废弃的回调地址应删除，
不要重复添加相同地址。

基础 URL 与重定向 URI 必须和 PAS 的外部可访问主机、协议、端口完全一致；不能只填写 PAS 根地址。
Microsoft Entra 会在授权开始前拒绝非 localhost 的 HTTP 回调（`AADSTS500117`），即使“公共客户端/
本机（移动和桌面）”页面允许保存该地址也不能用于 PAS。

#### 线下测试与线上部署

线下若仅验证目录同步，不需要配置回调地址。线下若验证 SharePoint 登录，应先用受浏览器信任的证书通过
HTTPS 反向代理或测试域名暴露 PAS；然后将该 HTTPS 基础 URL 写入 PAS 和 Entra。线上部署使用相同的
**Web** 平台和 HTTPS 回调配置。

### 第三步：在 PAS 创建 SharePoint 身份源

在 **用户** > **企业身份源** 中选择 **新增来源** > **SharePoint**，选择与第二步相同的**全球云**或
**中国云（世纪互联）**，再填写从 Entra 获取的目录（租户）ID、应用程序（客户端）ID 和客户端密码的
**值**。创建后点击**强制同步**，直到状态显示为 `active`。

PAS 会针对所选云环境用这些凭证换取 app-only Graph Token，只保存加密后的来源配置和同步目录事实。
完整快照写入后来源才会显示为 `active`；刷新失败时会变为 `stale`，最后一份完整快照在配置的宽限期内仍可使用。

SharePoint 用户和用户组主体使用 Entra 对象 ID。文档导入链路也必须把相同对象 ID 写入
PolarRAG ACL；PAS 不会按邮箱、UPN、展示名或 SharePoint 站点本地组 ID 猜测映射。

来源变为 `active` 后，用户可在 PAS 登录页选择**使用 SharePoint 登录**。PAS 会使用 PKCE、
Entra 签名密钥、issuer、audience 和 nonce 校验授权码响应。Entra 对象 ID 声明（`oid`）是稳定的
PAS 企业用户 ID；首次登录会创建一个无密码用户。已有 PAS 用户也可通过**绑定企业身份**关联到
已同步的 SharePoint 身份。

## 配置飞书身份源

飞书接入分为两步：先在 PolarDB Agentic 中配置 PAS，再在飞书开放平台配置应用。

### 第一步：在 PolarDB Agentic 中配置 PAS

PAS 是 **PolarDB Agentic Server**，即当前 MCPServer 的管理控制台和认证服务。**外部访问
基础 URL** 使用当前 MCPServer 对用户公开的访问地址：从浏览器地址栏复制当前控制台地址，删除
`/login`、`/users` 等页面路径、查询参数和片段，只保留协议、主机和端口。例如：

```text
https://pas.example.com
```

登录 PAS 后，进入**设置** > **配置** > **服务运行策略**，填写该地址到**外部访问基础 URL**，
执行检查并激活配置。生产环境必须使用可被用户浏览器访问的 HTTPS 地址。

### 第二步：在飞书开放平台配置应用

在[飞书开放平台](https://open.feishu.cn/app)创建并发布飞书自建应用。在**网页应用**中，将
**桌面端主页**填为第一步的 PAS 基础 URL；再进入**安全设置** > **重定向 URL**，添加以下两条
精确回调地址：

```text
https://pas.example.com/auth/feishu/tenant-verification/callback
https://pas.example.com/auth/feishu/login/callback
```

`tenant-verification` 用于验证并激活企业身份源；`login` 用于个人用户免密码飞书登录。漏配
`login` 回调会导致飞书返回 `20029`。

基础 URL 和回调地址必须与 PAS 的外部可访问主机、协议和端口完全一致。不要将 callback
地址填入桌面端主页。生产环境回调地址必须使用 HTTPS。

在**发布管理** > **创建/修改版本** > **可用范围**中，将管理员本人、管理员所在部门或
**全部成员**加入可用范围。验证身份源和登录 PAS 的用户必须位于该应用的可用范围内；修改后
请发布版本。

在飞书应用的**开发配置** > **权限管理**中打开**通讯录**，点击**配置**并在**数据范围**选择
**全部成员**；随后为该范围开通以下**应用身份**权限：

| 权限 | PAS 使用原因 |
| --- | --- |
| `contact:contact.base:readonly` | 读取通讯录基础信息。 |
| `contact:department.base:readonly` | 读取部门树。 |
| `contact:department.organize:readonly` | 读取部门父子关系。 |
| `contact:user.base:readonly` | 读取租户用户和部门直属用户列表。 |
| `contact:user.department:readonly` | 在用户事件中读取 `department_ids`，更新部门成员关系。 |
| `contact:user.employee_id:readonly` | 读取租户级 `user_id` ACL 标识。 |
| `contact:group:readonly` | 读取通讯录用户组及成员关系。 |

以上七项权限满足 PAS 目录增量同步所需的字段范围。修改权限后，请发布应用版本并在
PAS 控制台手动触发一次全量同步，以补齐此前未能写入的成员关系。若用户详情未返回
`department_ids`，PAS 会将该增量事件标为失败，不会把缺失字段误当成空部门列表。

进入**事件与回调**，选择**使用长连接接收事件**，并在发布应用版本前添加以下事件：

- `contact.user.created_v3`、`contact.user.updated_v3`、`contact.user.deleted_v3`；
- `contact.department.created_v3`、`contact.department.updated_v3`、
  `contact.department.deleted_v3`；
- `contact.scope.updated_v3`。

长连接由 PAS 主动连向飞书。不要配置事件回调 URL、Verification Token 或 Encrypt Key，也不需要
让飞书反向访问 PAS。用户事件更新对应用户及其成员关系；部门事件读取该部门的直属用户并更新成员关系；
用户删除事件会停用同步身份及其专属 PAS 账号，并撤销刷新会话；不会删除账号，也不会停用与该身份关联的
PAS 自建账号。全量对账对飞书中已不存在的用户执行相同处理。离职用户重新入职后，通讯录身份同步为活跃时
自动启用其专属 PAS 账号。
通讯录范围变更会触发一次全量对账。
飞书没有对应的通讯录用户组事件族或用户组变更日志游标。PAS 因此默认每小时只对账通讯录用户组及其成员，
不扫描全部用户和部门；管理员主动同步或达到配置的增量不可用阈值后的全量兜底可修复漏事件漂移。
全量及用户组与知识权限对账都会枚举两类通讯录用户组，再分页拉取各组的直属成员，
不会对每个通讯录用户分别发起两次归属查询。

文档 ETL 已展开文档 ACL 中的部门、通讯录用户组和群聊，并将规范用户成员关系持久化到
`acl_principal_membership`；可选 `acl_group` 也存储在同一快照。PAS 用该快照补充目录 API
提供的数据；用户、部门和通讯录用户组直接从飞书同步。目录同步应用可以不同于文档导入应用，但两者必须属于同一飞书租户，且
都使用租户级 `user_id`。
配置该快照后，用户事件会重新读取该用户的 ETL 成员关系；用户组与知识权限对账会保留 ETL 群聊成员关系。

### 创建、验证和绑定飞书来源

在 PAS 控制台打开**用户** > **企业身份源**：

1. 点击**新增身份源**，选择飞书，仅填写名称、App ID 和 App Secret。默认勾选的
   **绑定所有 Space**会绑定当前所有已启用 Space，并在以后有新 Space 注册到 PAS 时自动绑定；
   如需逐个配置可取消勾选。PAS 随后跳转到飞书。
2. 登录并授权应用。PAS 消费一次性 state，获取已验证的 `tenant_key` 后返回控制台；不会
   保存管理员的用户 access token。
3. PAS 会直接从飞书同步用户、部门、部门层级和通讯录用户组。为某个部门分配 Agent 时，其下级
   部门中的用户也会获得该 Agent。点击**权限数据源**可配置可选的 ACL 成员和知识范围快照。
4. 点击**绑定 Space**，在分页的**可绑定**和**已绑定 Space**页签中管理关系。两个页签都支持
   全选当前页和取消全选；可绑定页签批量绑定，已绑定页签批量解绑。下一次 ACL 计算起，被解绑
   来源的主体不再用于对应 Space。通过 API 主动解绑不会被页面读取自动补回。

在租户验证完成且首次目录同步成功前，来源保持待配置状态，不会贡献 ACL 主体。来源绑定仅让
同步主体成为该 Space 的候选主体，本身不会授予任何文档访问权限。租户验证完成后，即使某个飞书
用户尚未出现在已完成的目录快照中，也可以使用飞书登录；PAS 会在该用户首次成功登录时创建对应的
企业身份。

如果租户验证没有完成，先确认已激活的**外部访问基础 URL**和飞书**重定向 URL**中的地址
与上述 callback 完全一致；然后再次点击**验证飞书租户**。每次验证都会使用新的单次
state。

如需通过自动化管理身份源、用户映射或 Space 绑定，请参见
[企业身份源管理员 API](../reference/enterprise-identity-sources-api.md)。密钥只能放在密钥管理服务或
受保护的运行环境，不能写入 URL 或代码仓库。

## 验证同步

PAS 会立即启动已验证来源的首次同步；首次飞书全量同步完成后，PAS 通过长连接接收用户和部门事件，
已入队事件通常在 5 秒内开始处理，实际完成还取决于飞书推送和 API 耗时。默认每 10 分钟检查一次
全量兜底条件：只有增量持续不可用达到配置阈值（默认 24 小时）、且距上次全量至少经过同样时长，
才启动全量对账。连接异常时最多尝试建联 3 次；仍失败则进入 `error`，停止立即重连；用户组与知识权限仍按周期对账。
达到上述阈值时先重新建联（最多 3 次），再全量对账；建联失败也继续全量，状态仍为 `error`。
`contact.scope.updated_v3` 也会请求全量对账。用户组与知识权限独立于订阅状态，默认每小时扫描
用户组及成员，并读取已配置的 ETL 知识权限；用户组对账失败保留上一份完整目录快照并重试，不将整个来源标为 stale。
全量对账失败后会退避重试，包括手动触发和启动时触发的任务。
PAS 启动后会对非 `error` 来源请求一次全量对账，以补齐服务离线期间可能漏掉的变更；`error` 来源仍等待不可用阈值。同一来源的全量对账和用户组专项
对账不会同时执行：若用户组正在对账，全量会排队等待。用户和部门事件可以与用户组对账并行处理；
全量对账期间收到的事件会先入队，并在全量完成后幂等应用。
SharePoint 继续使用已配置的同步周期。未完成或失败的全量同步会按提供商游标在后台继续。
飞书**同步用户和用户组**会先返回并显示**全量同步中**；后台任务先处理已接收的增量事件，再开始全量。
来源正在同步时再次点击**同步用户和用户组**不会创建第二个任务。管理员
API 的同步、状态查询和错误处理语义参见
[企业身份源管理员 API](../reference/enterprise-identity-sources-api.md)。

页面的**增量订阅**列显示 `connecting`、`active` 或 `error`（旧版的 `connected_unconfirmed` 也按活跃显示）。
长连接建立即视为正常，长期没有事件也不会触发全量对账。所有订阅状态均显示上次全量时间，
无记录时显示“未执行”；`error` 另显示订阅异常提示。
PAS 在不可用阈值到达后先尝试建联，再全量对账。若连接仍失败，继续显示 `error`，下一次全量仍受阈值约束。
管理员修复飞书配置后可点击**同步用户和用户组**，无需等待阈值。即使增量订阅为 `error` 且全量兜底阈值尚未到达，
用户组与知识权限仍按独立周期对账。
飞书通讯录列表的分页标记不是可回放的变更游标；PAS 不依赖“上次同步版本”补事件。
先建联、再全量，并缓存全量期间收到的事件，是避免建联与快照之间出现空档的策略。
事件记录超过 7 天会清理；若过期事件尚未处理，PAS 会先请求全量对账，再删除该事件记录，
由提供商快照补齐变更。

PAS Dashboard 的**企业身份同步**模块可配置 `feishu_check_interval_seconds`（默认 `600`）、
`feishu_fallback_after_seconds`（默认 `86400`）和 `feishu_group_and_knowledge_scope_interval_seconds`（默认 `3600`）。
它们依次是全量兜底检查间隔、增量不可用触发全量的阈值和用户组与知识权限对账间隔；都不是定时拉取飞书用户、
部门增量的周期。`interval_seconds` 仍是 SharePoint 全量刷新周期（默认 `1800`）。修改后需激活配置。

飞书首次全量同步默认使用 2 路并发，后续全量对账默认使用单路并发，SharePoint 默认使用 8 路并发。
管理员可在配置页面的**企业身份同步**模块调整上述周期和飞书并发数。Docker 部署也可通过
`PAS_FEISHU_INITIAL_SYNC_CONCURRENCY`、`PAS_FEISHU_SYNC_CONCURRENCY` 或
`PAS_SHAREPOINT_SYNC_CONCURRENCY` 设置 `1` 到 `32` 的整数。不同身份源可以并行，但同一来源在全部 PAS
副本间只有一个由数据库 lease 保护的同步任务。飞书或 SharePoint 连续返回 HTTP 500/503 时，会从 1 分钟开始
指数退避，最长 30 分钟；HTTP 429 会在边界内采用数值型 `Retry-After`。其他失败会等待已配置的同步周期。手动同步在请求预算
耗尽后会先返回；完整目录尚未完成时，后台会继续执行。每个完成的提供商分页会立刻写入已配置的 PAS
元数据库；持久化 `/var/run/pas` 断点仅保存提供商游标和待处理工作，不保存完整目录。只有全量同步完成并提交后才会删除该
断点文件。

`active` 表示最新快照已完成。`stale` 表示最近一次刷新失败；PAS 会在该来源配置的宽限期内继续使用最后一份
完整快照，默认宽限期为 7 天，管理员可在编辑来源时调整。宽限期过后，PAS 会排除该来源，直到后续同步成功。
`last_error` 只包含脱敏后的错误类型。飞书成员关系部分成功则使用独立的 `sync_warning`：只记录稳定
warning code、跳过用户组数和 provider code 计数。控制台会展示该 warning，PAS 会保留这些用户组上一次的
成员关系；下一次完整且无 warning 的同步会清除它。请按时间在受保护的 PAS 日志中排查，不能记录或分享
应用密钥、快照账号密码。

外部 Token 兑换（飞书 UserInfo、introspection 加 UserInfo）、登录、Agent 成员判断、ACL 上下文和
基于身份源的 PERSONAL owner 映射采用相同的有效期规则。未过期的 `stale` 状态本身不会阻断 Token
校验；上游 Token、租户、主体和 audience 检查仍然执行。没有成功快照的 stale 来源、已过期的 stale 来源、
已禁用或待验证/绑定来源仍不可用。身份源响应提供 `snapshot_usable`，外部应用测试弹窗据此使用服务端的有效性判断。

对一个测试用户，核对租户级 `user_id` 和预期主体 ID 是否与 PolarRAG 文档 ACL 完全一致。
PAS 会产生 `user`、`department`、`group` 和 `acl_group` 主体。主体 ID 不透明且区分大小写。
来源绑定和同步成功均不会绕过 PolarRAG 的 Space、知识库、owner 或文档 ACL 检查。

## 登录和编辑

目录同步会创建或更新无密码 PAS 用户。用户可在 PAS 登录页选择**使用飞书登录**；PAS 校验单次
授权响应与已验证租户一致，并在用户首次登录时自动创建账号。不要给已同步身份设置密码。

所有企业身份源均遵循同一规则：同步发现通讯录用户不存在或已停用时，停用其专属 PAS 账号并撤销刷新会话；
同步发现用户活跃时，重新启用原账号。对专属账号在 PAS 中手动修改的状态会被下次同步覆盖；
与企业身份关联的 PAS 自建账号仍由管理员手动管理。

自动停用仅适用于该身份源拥有、使用规范外部标识且只有一个外部身份的 OIDC 账号。
关联的本地账号、具有其他身份的账号，以及其他身份源拥有的账号，保留其 PAS 状态和会话。
移除用户时会撤销控制台刷新令牌、OAuth 刷新令牌和外部令牌会话；重新启用账号不会恢复已撤销的令牌。

当某个 provider 仅有一个可用身份源时，对应登录操作会直接跳转到该 provider。最近同步的
`stale` 身份源在配置的快照有效期内仍可用于登录。同一 provider 存在多个可用身份源时，
PAS 会先展示来源选择页；用户选择企业身份源后再继续 provider 登录。PAS 将选中的来源绑定到
一次性 state；回调不接受用户提供的来源或租户选择。

来源表可查看已同步用户和组。编辑飞书来源时需要再次输入 App ID 和 App Secret，并重新验证
租户；删除来源会撤销目录数据、Space 绑定和 Agent 组授权，但不会删除已存在的 PAS 用户。

编辑 SharePoint 来源时需要重新填写租户 ID、客户端 ID 和客户端密钥。已存在的 SharePoint 用户
会话保持有效，下一次登录会使用更新后的应用注册配置。

## 用户身份映射与 PolarRAG 访问

**用户**列表会在用户名下展示租户级外部 `user_id`，并在独立的**身份来源**列展示来源标签。**部门**
单元格会汇总本地 PAS 部门以及只读的企业部门和通讯录用户组。`PAS` 表示本地账号；飞书或
SharePoint 标签表示已同步的企业身份。组织信息为空表示该来源没有返回该用户的成员关系。

PAS 会在服务端构造的 `acl_context` 中始终附加该用户稳定的
`polarrag:user` 别名。同步用户的别名基于其 PAS external ID；管理员将该企业身份绑定到已有
PAS 用户后，PAS 还会在该身份源已绑定的 Space 内保留同步账户的来源原生别名。这样，原同步账户
已拥有的 Personal 知识库和文档仍可由绑定后的 PAS 用户访问，同时请求仍携带飞书或 SharePoint
用户和用户组主体。PAS 不会将任一别名投影到未绑定或已过期的身份源。

仅当需要把已有本地 PAS 账号关联到一个同步企业用户时，才使用**绑定企业身份**。这是一条由管理员
维护的映射，可编辑、可移除；相同页面还允许管理员为该 PAS 用户新增、停用或删除手工维护的 Feishu、
SharePoint 或原生 PolarRAG 主体。不要按邮箱或显示名称猜测映射，应从已同步身份中选择，以确保
PAS 使用稳定的外部用户 ID。

绑定后，同步账户仍会显示在**用户**列表中；其**企业身份**面板会继续展示该身份，并标记为
PAS 管理的映射，同时显示目标 PAS 用户的原生别名。移除映射后，该身份恢复为同步身份模式。

## Agent 群组访问

常规配置直接从 Agent 详情页使用**配置企业访问**。该可预览操作一次选择一个有效 Source、
同步组或 PAS 用户、活动的 PolarRAG 实例，并从每个所选实例中至少选择一个已启用 Space。
应用预览时会原子创建缺失的 Agent-实例绑定和 Source-Space 绑定；预览会区分 Agent 局部授权、
全局变更和将复用的既有关系。

PAS 每次 Agent 访问都会校验当前成员关系；用户离开群组、群组被禁用或来源变为过期状态后，
对应的群组派生 Agent 访问会立即失效。从 Agent 删除具体用户、组或全部同步用户授权，不会
删除全局 Source-Space 绑定、Agent-实例绑定或共享 PUBLIC 范围。

**企业身份源 · 全部同步用户** 是独立且可移除的显式授权项，展示在首位且绝不默认勾选。它仅在来源保持有效且未过期时，
覆盖该来源当前及后续同步的有效用户；不会包含无关的 PAS 用户，也不会绕过 PolarRAG 的文档
ACL。控制台支持多选用户或用户组；**全选用户组** 会刻意排除身份源全员项，因此来源全员授权
始终需要管理员明确选择。

既有身份源 Space 页面以及 Agent 用户/组控件仍保留，用于高级细粒度管理。

## 配置知识库权限数据源

在已验证的飞书来源行选择**权限数据源**，选择 MySQL（默认端口 `3306`）或
PostgreSQL（默认端口 `5432`），填写地址、数据库、只读用户名和密码。数据库默认值为
`polar_rag_meta`。PAS 需要对 `acl_principal_membership`、`external_kb_scope_snapshots`、
`external_kb_scope_grants` 三张表具有 SELECT 权限。

密码由 PAS 配置密钥加密保存，不通过 API 返回，也不会回填表单。编辑已有连接时，密码留空表示
保留原密码；填写新密码则替换。保存不改变身份源状态。绑定目标 Space 后通过 **同步知识库权限** 验证连接并拉取权限。

此连接同步已有知识库的权限，不导入飞书文档，也不创建知识库。自动绑定要求 Agent 使用 SCOPED 模式、
启用 `external_knowledge_auto_bind_enabled`，且已有全局 KB 资源的 Space 与 KB ID 匹配快照。

管理员可进入**Agent 详情 → PolarRAG 实例 → 绑定知识库**，操作
**自动绑定外部知识库**开关。仅 SCOPED Agent 展示此开关，LEGACY_ALL Agent 隐藏该入口。
开关回显已保存状态，默认关闭。等价的管理员 API 为
`PUT /api/admin/agents/{agent_id}/external-knowledge-auto-bind`，请求体为 `{"enabled":true}`。
开启会投影已有权限快照，
并在后续同步时继续更新，范围限于 Agent 的全局知识库范围。此开关不改变 Agent 访问模式，
应先配置知识库和用户权限，使按范围授权生效。关闭会移除该 Agent 的同步权限范围及用户绑定，
保留手工绑定。加载或保存失败会提示错误，保存失败时保留原状态。

两种数据库均以有界 keyset 分页读取成员关系和权限授予，每次查询最多 1,000 行。每次分页读取采用
只读 repeatable-read 事务；只有一个 scope 的所有授权分页读取完成后才会导入，读取失败不会发布
不完整的授权集合。成员关系仍汇总用于目录对账；权限导入时只缓冲一个完整 scope 的授权集合。

Dashboard 配置字段为 `feishu_group_and_knowledge_scope_interval_seconds`，默认 `3600`、最小 `600`。
已有配置中的旧字段 `feishu_group_interval_seconds` 仍可读取；新配置响应和 schema 使用新字段名。

独立的知识库权限同步直接分页读取权限记录，不全量加载目录成员关系。连接验证仅检查只读访问权限。

保存 ETL 配置保持企业身份源状态、目录同步时间和目录错误不变，并将独立的连接验证结果标记为未验证。
绑定已有知识库所在 Space 后，打开 **同步知识库权限**：**验证连接** 仅检查 ETL 表的只读访问；
**立即同步权限** 导入最新知识库权限快照，并重计算已开启自动绑定的 Agent。连接验证结果与权限
同步时间、处理/跳过快照数分别记录。失败不会改变身份源状态或导致目录登录不可用。
该入口不拉取通讯录、不创建用户映射、不替代现有周期性目录/群组同步。每个来源同一时间仅运行一个
ETL 操作，操作限时 120 秒，异常退出的任务租约在 300 秒后可重试。运行时不允许编辑 ETL 配置；
状态读取失败时使用 **刷新结果** 重试。

SCOPED Agent 开启自动绑定后，可在知识库绑定页面点击 **更新自动绑定**。此操作仅使用 PAS
已导入快照重新计算当前 Agent，不读取 ETL、不切换自动绑定开关、不改动手工范围。上游权限有变化时
先在身份源上拉取 ETL 权限。用户映射、Agent 用户/群组访问、Space 绑定及全局 KB 范围需已配置。
结果展示处理/跳过快照数和生成绑定数；零绑定可能表示缺少访问映射。

### 通过文件权限发现知识库

飞书 ETL 也会发布 `document_read_discovery` 范围。用户对至少一个已成功索引的
文件拥有 READ、WRITE 或 MANAGE 权限时，即使不是所属 Wiki 空间成员，也可以
发现文件所在的已有知识库。PAS 通过同一 ETL 权限数据库连接导入这些范围。
将 Agent 配置为 SCOPED，开启**外部知识库自动绑定**，并将目标知识库纳入其
全局范围即可。不需要新增数据库表或控制台开关。

只有当前、有效且经 Search 确认已生效的 ACL 代际贡献授权。待处理、STALE、
已删除或不支持的文件 ACL 不贡献授权。ETL 会合并同一知识库多个 Link 的文件；
撤销最后一个可读文件的权限后，在下一轮 ETL 刷新和 PAS 范围对账后移除该
发现授权。独立的 Wiki 空间授权和手工绑定继续生效。

发现知识库不会授予其中所有文件的访问权限。PolarRAG 每次检索仍执行文件级
权限检查。发现结果最终一致：先由 ETL 任务刷新，再由 PAS 按配置周期或
**立即同步权限**导入。已索引文件若没有当前且确认生效的 ACL，可能在 ACL 对账
成功之前仍不出现在发现结果中。


### 权限拉取与自动绑定的区别

周期性用户组／知识库权限对账先调用飞书群组 API，再通过只读快照客户端读取已配置的权限数据库。
因此飞书 API 失败可能阻止后续数据库读取。开启或更新 Agent 自动绑定只使用 MCP 已导入快照，
操作成功不能证明上游数据库连接或数据新鲜度。**同步知识库权限**使用同一数据库配置及连接客户端
拉取上游权限记录，跳过飞书目录／群组 API 和目录成员关系汇总，不改变身份源生命周期状态。

用户组／权限同步失败使用配置的用户组／知识权限周期作为兜底重试间隔，不使用全量目录兜底阈值。
调度器会把已有的异常过长群组重试时间修正为该次检查之后一个配置周期；保留有效租约及正常退避
（包括最长 30 分钟的 HTTP 重试退避）。修正仅改变群组重试时间，不改变身份源状态或成功同步时间。

## 配置钉钉身份源

用户绑定选择器会为已关联钉钉身份的用户显示已注册的钉钉身份源名称；该名称与绑定上展示的继承权限来源分别显示。


同一 Space 关联多个身份源时，Agent 权限刷新按各知识库实际存在的完整快照处理。某身份源既无该知识库的上游快照，也无已导入快照或派生绑定时，可略过该身份源；已有管理记录的身份源缺失快照时，仍停止整个知识库的刷新并保留原绑定。显式的完整零授权快照仍执行撤权。每个已完成知识库的结果会记录略过的身份源 ID。


若登录入口返回 HTTP 409，管理员需先登录 PAS，进入**企业身份源**，点击**验证钉钉企业**，完成浏览器授权并同步目录。待验证身份源不能发起普通登录；企业验证完成后，“同步用户和用户组”使用与周期同步相同的钉钉目录适配器；失败页面会提示上述配置步骤，不暴露身份源配置。钉钉会话包含当前凭据版本（credential epoch），以支持已经关联钉钉身份的本地账号认证。


使用企业内部应用和普通员工账号。在钉钉配置网页授权回调
`<PAS 外部访问地址>/auth/dingtalk/callback`，授权 `openid corpid`。
请先将 `runtime_policy.external_base_url` 配置为 PAS 对外可访问的基础 URL 并激活。
该 URL 缺失或无效时，企业验证和登录返回 HTTP 409，不会发起授权或创建浏览器 state cookie。
配置 URL 后即可重试；PAS 不会根据浏览器地址或转发头推断回调来源。
配置应用可见
通讯录范围以及 unionId 转 userId、用户详情、授权范围、直接子部门和分页部门用户
查询权限。开启 Stream 事件订阅：`user_add_org`、`user_active_org`、`user_modify_org`、`user_leave_org`、
`org_dept_create`、`org_dept_modify`、`org_dept_remove`。参考
[官方 Stream SDK](https://github.com/open-dingtalk/dingtalk-stream-sdk-python) 和
[钉钉授权指南](https://open.dingtalk.com/document/orgapp/tutorial-obtaining-user-personal-information)。

新增 **钉钉** 来源：`tenant_id` 填 corpId，`client_id` 填 AppKey，`client_secret` 填
AppSecret。浏览器验证选定企业后，绑定目标 Space 并同步目录。用户 token 必须返回
匹配的 corpId；PAS 还通过应用授权的 unionId 转换和用户详情核实内部员工身份。
修改应用凭据会撤销验证，并使旧的单次浏览器 state 失效。用户 token 交换仅接受
明确配置的钉钉信任来源，调用方不能指定受信任的 userId/unionId。

PAS 使用 `dingtalk:<corpId>` 保存企业 userId；部门使用字符串形式的原生数字 ID。
支持 USER、DEPT、ORG；TAG、CONVERSATION、DYNAMIC_GROUP 不授予知识库发现权限。
同一个 `identity_domain` 只能绑定一个钉钉企业。本地部门和手工主体映射不能替代
钉钉目录事实。

每五分钟全量对账，目录有效期最多十五分钟，即使状态为 ACTIVE 也不能超期。
Stream 通知按来源、事件和主体持久化去重后才确认接收，复用飞书的事件收件箱、
重试及事务围栏。用户事件只暂停受影响目录用户及其成员关系，部门事件暂停该部门
的继承权限。PAS 回查当前权威事实和应用可见范围，不直接套用事件差异；晚到的
离职或删除事件不能覆盖当前仍存在的员工或部门。缺少主体 ID、子树范围不明或
事件重试耗尽时转全量对账。正常连接轮转直接重连，不递增故障计数；每次新建连接成功后请求一次全量补偿，
覆盖可能漏掉的事件。禁用或删除
来源后释放监听器。全量扫描不能覆盖更新的事件或已变更的凭据。分页失败不会发布部分目录。扫描上限为五万条，
进程恢复后重新扫描，不恢复部分分页游标。

使用只读账号配置 ETL 权限数据库。PAS 只读取选定企业的 `source=DINGTALK` 快照；
ETL 的观测时间必须在十五分钟以内。无变化重跑保留 generation 和语义更新时间。
文档发现要求 Search ACL 已应用、文件未删除且上传完成、文档 ID 匹配；按来源、
企业、Space、KB 聚合所有链路。仍要求 Agent 成员、SCOPED 模式、显式自动绑定及
全局资源范围。发现知识库不等于可读其中所有文档，Search 最终校验文档 ACL。
测试链路建议使用不超过五分钟的同步间隔，以保持权限观测新鲜。

### 维护部署边界

本适配是 **CONTRACT** schema 发布，generation 2，扩展已发布的 provider CHECK
约束，并增加浏览器 state 和健康存储。普通托管滚动迁移拒绝旧数据库；停止全部
旧读写进程，备份配套的数据库、root key、配置，再执行：

```shell
pas database inspect
pas database migrate --maintenance --operation-id dingtalk-identity-v1
pas database migrate --maintenance --operation-id dingtalk-identity-v1
pas database check
```

先在隔离数据库副本验证完整流程。旧镜像按设计拒绝 generation 2；回退必须同时
恢复迁移前数据库和配置及旧镜像。新空库可初始化，已完成的迁移可重放。本分支不能
用于普通托管滚动升级，除非另行评审并落实兼容设计。

Stream 连接与关闭均设有超时。连接成功显示“订阅正常”；失败记录为“订阅异常”，并指数退避重试，最长间隔 60 秒。目录全量同步成功不代表 Stream 健康。全量对账使用配置间隔与 300 秒的较小值，部门用户每页查询 100 人；顶层授权部门显示真实名称。上游瞬时网络、429 或 5xx 错误仅保留尚在有效期内的已有快照；快照被拒或配置错误仍立即使快照失效。增量事件不推进全目录同步时间；受影响用户的来源派生直接授权和旧手工群映射不能绕过暂停。全量对账仍最多间隔 300 秒，保持现有 900 秒信任上限，不照搬飞书较长的全量兜底周期。同一身份域绑定不同钉钉企业时，手动和自动绑定均返回 HTTP 409。

### 钉钉兼容性与群聊边界

钉钉外部用户与飞书用户使用相同的目录新鲜度检查。外部 Token 配置保留 `dingtalk` 提供方及已配置的固定身份源。手动用户主体映射支持钉钉，身份域用户列表包含这些映射。手动钉钉会话群在写库前明确拒绝；部门授权使用身份源目录部门。本次补齐不需要数据库迁移。

ETL 保留 `CONVERSATION`、`TAG` 授权，但不据此授予知识库发现权限或推导用户成员。`DYNAMIC_GROUP` 在严格归一化时失败。群信息查询成功不证明成员可读；当前应用凭证的成员查询仍受阻，尚未找到公开的 `openConversationId` 到 `chatId` 反查接口。

钉钉浏览器登录仅验证身份，不保留钉钉委托凭证，也不代表已授权 DWS Chat MCP。未来用户委托展开需要独立授权、凭证生命周期、完整分页及员工 ID 映射验证，不纳入本次已支持范围。
