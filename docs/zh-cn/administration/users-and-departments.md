# 用户与部门

[English](../../en/administration/users-and-departments.md)

控制台将员工归入**访问管理 → 个人账号**，Agent 归入**服务账号**。通过**资源**管理数据库授权，通过**连接 MCP**直接以个人身份访问，无需 Agent。下文的既有高级配置和 Agent 连接继续支持。参见[账号与资源](accounts-and-resources.md)。

管理员在 Web 控制台管理人类身份和组织访问。Agent 身份相互独立，在
**Agents** 中管理。

## 用户

进入 **Users** 并点击 **Create User** 创建内置用户。填写唯一登录用户名、由
管理员设置且至少八个字符的初始密码和角色；显示名称与邮箱可选。新用户创建后
立即处于 active 状态。SSO 用户按已配置的身份声明匹配。管理员可以启用、停用、
重置或删除用户；停用会阻止新的认证和授权。

**用户**页面在服务端完成搜索和分页，不会先下载完整用户目录再过滤。企业身份选择器
同样在服务端分页加载同步用户和组，因此大租户不会阻塞页面首次渲染。用户编辑器中的
部门选择器也会在后端搜索，而不是下载全部部门；当前已选但不在返回分页内的部门仍会保留。

用户实例访问需要选择已注册实例、有效的 `direct_access` 凭证、
`readonly` 或 `readwrite` 权限和显式能力。只授予 MySQL 账号允许的数据库和
操作；PAS 不会提升后端权限。

人类 User 只使用管理员分配的已注册实例，不会领取 自动供给池成员、消耗 Agent
购买预算或触发物理冷创建。没有分配注册实例时，请求返回
`NO_INSTANCE_ASSIGNED`，管理员需要先注册并分配实例。

## 部门

部门用于组织用户，并可引用一个已经注册的 `multitenant` 实例。实例注册和
凭证轮换仍在 **Instances** 中完成。部门成员关系不会复制密码，也不会创建
新的物理实例。

部门供应通过所选后端创建逻辑租户资源。删除部门或绑定属于管理操作，执行前
应检查自有资源和清理状态。

飞书部门授权遵循同步后的层级：为父部门分配 Agent 会包含所有下级部门成员，但为
子部门分配不会反向授权其父部门或兄弟部门。用户 ACL context 会从每个直接所属部门
向上展开到全部祖先部门，并同时包含已同步的企业用户组。

## 安全管理

管理员账号和数据库账号应相互独立；人员变动后复查绑定，并在角色、状态、
部门、凭证或实例访问变更后检查 Audit Logs。
