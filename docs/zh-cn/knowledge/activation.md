# 启用与停用知识库

[English](../../en/knowledge/activation.md) | **简体中文**

新安装默认关闭知识库。MySQL 注册、SQL 访问、Agent 和认证可以独立使用。
升级缺少 `knowledge` 配置的存量安装时，保留原有启用行为。本功能沿用现有
元数据 schema；启用功能不会执行 Alembic。

## 自托管实例启用

1. 管理员登录，进入 **功能管理 → 知识库**。
2. 选择 **启用知识库**，选择已保存连接，或保存已有 PolarRAG 服务的连接。
   保存连接仅表示保存草稿，不代表获得读取权限。PAS 不创建或购买上游服务。
3. 检查连接，选择知识空间、知识资源和已有 PAS 用户。**验证读取权限** 使用
   受保护的搜索 API 检查所选身份，不自动授予权限。空间使用企业 ACL 时，先配置
   匹配的企业身份绑定。
4. 选择 **保存并启用**，状态变为 `PENDING_RESTART`。重启 PAS 容器或进程；例如
   Compose 服务名为 `pas` 时执行 `docker compose restart pas`。请使用部署文件中的
   实际服务名。
5. 等待 `ENABLED`，重新连接 MCP 客户端以刷新工具目录。实例和 Agent 页面随后
   显示知识管理入口。上传和 OSS 按需参照[管理员接入指南](polarrag-onboarding.md)配置。

首次重启装配知识 API、MCP 工具、目录同步和上传清理任务。保存配置不会在运行中
加载或卸载 Python 模块。`ENABLED` 表示配置已生效；上游服务随后不可达时，请求
仍然可能失败。

自托管单副本在启动验证后自动确认。多副本应重启全部副本、核对完整部署拓扑，
确认所有预期副本都以目标版本运行后，再选择 **确认全部副本**。心跳过期不能证明
失联进程已经停止。自托管的确认是运维操作，不是自动发现全部副本的保证。

## 安全停用

选择 **开始停用**，停止接受新的知识请求，并继续处理上传清理。卡片显示在途操作、
未解决上传、清理记录及正在执行的目录同步。全部归零后选择 **保存停用状态**，
再重启 PAS，状态变为 `DISABLED`。数据、连接和凭据保留，供后续重新启用。

清理受阻时，保持服务运行并处理相应工作。需要重试目录同步时，先取消停用，
重新同步，然后再次排空。不要通过删除上传清理记录绕过未解决的外部操作。
进程中途退出后，其准入记录不会自动过期：先停止或隔离该进程，检查上游操作结果，
核对并修复上传、清理或目录状态，再由运维人员在备份后通过 `config_version`
条件更新，仅修复 `feature.knowledge.admission` 中已确认过期的那一项操作。
禁止清空整条记录或修改已生效版本以强行通过。保留键属于运维状态，不属于功能配置。

启动读取验证失败时，MySQL 仍可使用，知识卡片报告 `FAILED`。修复上游身份或连接，
重新打开向导保存并验证修正后的连接，或保存停用配置，然后重启。配置回退应产生
新版本，不能倒退版本号或删除知识数据。

## 托管部署

管理员在 PAS 的 **高级设置 → 功能管理 → 知识库** 配置知识库。使用与自托管相同的
连接、空间和受保护读取校验向导，完成后选择 **保存配置**。保存产生目标版本并显示
`PENDING_RESTART`；它不会自动提交重启任务，也不会开放知识请求。

在管控控制台使用 **重启实例** 生效。管控在串行重启前从全部副本读取目标版本及
启停值，并将目标固定在工作流初始化输出中。每个副本必须加载并验证这个相同的目标。
确认物理拓扑和全部当前副本 ID 后，管控才确认启用。`ACTIVATING` 表示最终确认
尚未完成；请等待 `ENABLED` 后再让 MCP 客户端重连。PAS 浏览器用户即使是管理员，
也不能自行确认托管实例的全部副本已就绪。

停用时，先在 PAS 完成排空并保存停用配置，再执行实例重启。滚动期间不要修改目标
配置；版本变化或副本失败会阻止任务完成，应修复后重试。配置回退需保存新版本，
并在处理原任务后发起新的重启。MySQL 可用性取决于剩余服务容量：普通知识库滚动
流程要求另有一个健康且正在服务的副本，单副本需要单独规划维护流程。

**先发布支持在普通实例重启中发现知识库配置的管控组件，再发布本次 PAS 页面变更。**
旧管控如果只重启进程而不验证、确认知识库，功能可能停在 `ACTIVATING`。
已有任务保留初始化时记录的目标；要应用初始化之后保存的配置，应发起新的重启任务。
此流程不需要新增重启 API、反向回调或供 PAS 调用管控的凭据。

管理监听器继续提供经过认证、绑定实例与 generation 的
`POST /api/internal/v1/features/knowledge`，请求包含协议版本 `1`、`target`、
`action` 和 `parameters`，要求已有托管实例身份绑定。
支持的操作仍为 `status`、`options`、`save_connection`、`check_connection`、
`prepare_space`、`test`、`config`、`drain`、`cancel_drain` 和 `confirm_activation`。
`config` 仅允许 `knowledge` 模块的 `describe`、`save_draft`、`validate`、`activate`。
公开配置接口要求管理员身份和浏览器 CSRF 校验；直接使用 `reset`、`skip`、`disable`
命令不能绕过托管功能流程。管理员初始化 API 仍仅用于账号初始化。
启用知识库不会授予资源访问权限，也不会修改 ACL。

## 状态与兼容

| 状态 | 含义 |
| --- | --- |
| `DISABLED` | 未装配知识 API、工具和任务。 |
| `PENDING_RESTART` | 保存版本与加载版本不同。 |
| `ACTIVATING` | 副本已准备，等待整个部署确认。 |
| `ENABLED` | 已加载版本允许接受知识请求。 |
| `DRAINING` | 停止新请求，等待既有工作完成。 |
| `FAILED` | 启动验证失败，请查看脱敏错误码。 |

停用时访问旧知识 HTTP 地址会返回 `503 KNOWLEDGE_NOT_ENABLED`，不会误返回 HTML
页面。MySQL 路由仍可使用。功能状态保存在 `module.knowledge` 和保留键
`feature.knowledge.*` 中，不应通过通用配置编辑器修改这些状态记录。

Schema 兼容参见[升级与回滚](../deployment/upgrade-and-rollback.md)，配置协议参见
[引导式配置](../configuration/guided-configuration.md)。
