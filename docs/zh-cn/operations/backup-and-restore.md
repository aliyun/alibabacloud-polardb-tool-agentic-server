# 备份与恢复

[English](../../en/operations/backup-and-restore.md)

可恢复的 PAS 部署必须同时具备元数据库和与之匹配的根加密密钥。

## 备份

迁移前以及组织恢复计划要求的周期内，使用数据库原生一致性备份。将
`PAS_ENCRYPTION_KEY` 独立备份到批准的密钥管理系统，并记录备份对应的应用
镜像 digest 和 Alembic revision。

应用日志不是功能恢复必需项，但审计策略可能要求保留。Docker 命名卷和
Kubernetes `emptyDir` 日志不能代替外部备份。

## 恢复

准备兼容的 MySQL 或 PostgreSQL 数据库，恢复元数据并提供完全相同的原根
密钥。先使用相同应用版本执行 `pas database check`，再开放流量。恢复后还要
升级时，应先备份已恢复数据库，再执行迁移。

## 恢复限制

根密钥丢失或改变会导致加密模块密钥、数据库凭证、Agent Token 和共享 JWT
密钥材料无法读取，系统无法自动重建。只有数据库而没有密钥不构成完整恢复集。

恢复旧数据库也可能恢复旧 Token 和绑定状态。灾备演练后应吊销或轮换受影响
的凭证。

## 验证

定期在隔离环境测试恢复。验证 Schema 状态、管理员登录、每个副本配置就绪、
MCP 认证、已注册实例测试和一次受控 SQL 查询。
